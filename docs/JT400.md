# JT400 JDBC driver setup

Db2iLens talks to IBM i through **JayDeBeApi** + the open-source **JT400** JDBC
driver (`com.ibm.as400.access.AS400JDBCDriver`). The JAR is **never committed**.

## Requirements

- Java 11+ available on `PATH` (`java -version`)
- Python deps from the project (`jaydebeapi` is already declared)

## Install the JAR

```bash
# downloads jt400.jar into ~/.db2ilens/jt400.jar
./scripts/fetch_jt400.sh
```

Or set an explicit path:

```bash
export JT400_JAR=/absolute/path/to/jt400.jar
```

Resolution order used by the connector:

1. `JT400_JAR` environment variable
2. `./jt400.jar` (current working directory)
3. `~/.db2ilens/jt400.jar`

## Password handling

Never pass the password on the CLI.

```bash
export DB2ILENS_PASSWORD='your-secret'
db2ilens scan --host pub400.com --user YOUR_USER --schema YOUR_LIBRARY \
  --out scan.yaml
# or:
printf '%s\n' "$DB2ILENS_PASSWORD" | db2ilens scan \
  --host pub400.com --user YOUR_USER --schema YOUR_LIBRARY \
  --password-stdin --out scan.yaml
```

## Smoke check

With `PUB400_USER` / `PUB400_PASSWORD` (and optional `PUB400_SCHEMA`) set, the
integration test in `tests/test_ibmi_jdbc_integration.py` exercises a live
catalog read. Without those variables the test is skipped (CI stays green).
